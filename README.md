# TFG RAG: Naive vs Hybrid Retrieval-Augmented Generation

Python project for implementing, comparing and evaluating two retrieval-augmented
generation pipelines focused on AI compliance documentation:

- **Naive RAG**: dense retrieval with LangChain and ChromaDB.
- **Hybrid RAG**: dense retrieval with ChromaDB combined with lexical BM25 retrieval,
  reciprocal rank fusion (RRF) and an optional reranking stage.
- **No RAG**: baseline that sends the question to the LLM without retrieved context.

The configured corpus currently contains PDF guides and regulations in Spanish under
`data/raw/`. The ingestion process also supports `.txt` and `.md` files.

## Project Structure

```text
config/                 YAML settings and prompts
data/raw/               Source documents (.pdf, .txt, .md)
data/processed/         Generated chunks.jsonl
data/eval/              Evaluation CSV files
outputs/indexes/chroma/ Persistent shared ChromaDB dense index
outputs/indexes/dense_manifest.json Shared dense index manifest
outputs/indexes/hybrid_manifest.json Shared hybrid/BM25 manifest
outputs/indexes/lexical/ Inverted BM25 index
outputs/runs/           JSON files generated by QA runs
outputs/reports/        RAGAS and comparison reports
outputs/logs/           Pipeline logs
src/                    Application, ingestion, retrieval and evaluation code
scripts/                Direct ingestion, QA and evaluation scripts
tests/                  Automated tests
```

## Configuration

The application reads `config/settings.yaml` and optionally loads a local `.env`
file. There is no `.env.example` in the repository, so create `.env` manually in
the project root with at least:

```dotenv
OPENAI_API_KEY=your-api-key
OPENAI_MODEL=gpt-4o-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small
HF_TOKEN=your-hugging-face-token
```

`OPENAI_API_KEY` is required by the embedding and generation components. `HF_TOKEN`
is required to authenticate with Hugging Face and obtain faster model downloads.
The reranker weights are then stored in the local Hugging Face cache and reused by
later runs. The model variables can also use any model supported by the configured
LangChain OpenAI classes. Do not commit `.env` or API keys.

The current YAML defaults are:

| Setting | Value |
| --- | --- |
| `top_k` | `5` |
| `initial_k` | `20` |
| `chunk_size` | `600` |
| `chunk_overlap` | `120` |
| `hybrid_fusion_strategy` | `rrf` |
| `hybrid_dense_weight` / `hybrid_bm25_weight` | `0.6` / `0.4` |
| `reranker_enabled` | `true` |
| `reranker_model` | `BAAI/bge-reranker-base` |

Paths default to `data/` and `outputs/`. They can be changed with
`DENSE_INDEX_DIR`, `CHROMA_PERSIST_DIR`, `DATA_RAW_DIR` and
`DATA_PROCESSED_DIR`. The loader also reads `TOP_K`, `CHUNK_SIZE` and
`CHUNK_OVERLAP`; the corresponding values in `config/settings.yaml` take
precedence when they are explicitly defined there.

Prompts are stored in `config/prompts.yaml`. The QA prompt instructs the model to
answer only from the retrieved context and to acknowledge when that context is
insufficient.

## Ingestion and Indexing

Add source files to `data/raw/`, then run the unified indexer:

```bash
python scripts/ingest.py
```

The command preprocesses and chunks the corpus once, rewrites
`data/processed/chunks.jsonl`, builds the shared ChromaDB dense index, builds the
Hybrid RAG BM25 index in `outputs/indexes/lexical/`, and publishes the dense
and hybrid manifests in `outputs/indexes/`. `ingest_naive.py` and `ingest_hybrid.py` remain compatible
wrappers for the same command. Existing Chroma documents are removed before
rebuilding, so repeated ingestion does not duplicate chunks.

## Run Questions

The RAG commands expect their corresponding index to have been ingested first.
Query execution reads the processed chunks and validates the corresponding
manifest, corpus hash, embedding model, chunk IDs and Chroma metadata; it does
not reparse or rechunk files in `data/raw/`. On the first hybrid run, the
reranker is downloaded from Hugging Face and cached locally; later runs reuse the
cached weights.

```bash
python scripts/run_without_rag.py "Your question here"
python scripts/run_naive_rag.py "Your question here"
python scripts/run_hybrid_rag.py "Your question here"
```
Each run prints the answer and stores the complete payload, including the question
and retrieved context, in `outputs/runs/` with the pipeline name and timestamp.
Detailed stages are written to `outputs/logs/ingest_hybrid.log` during indexing and
`outputs/logs/hybrid.log` during querying. Dense retrieval is reported as Chroma
vector similarity; lexical retrieval is reported as the inverted BM25 index.

## Evaluation

Create a CSV in `data/eval/` containing at least these columns:

```csv
question,ground_truth
What is an AI regulatory sandbox?,A controlled environment supervised by a competent authority.
```

Evaluation currently matches the question from one run file against that CSV and
generates RAGAS metrics for that run:

```bash
python scripts/evaluate_naive.py outputs/runs/naive_<timestamp>.json data/eval/ground_truth.csv
python scripts/evaluate_hybrid.py outputs/runs/hybrid_<timestamp>.json data/eval/ground_truth.csv
```

Reports are written as CSV and JSON under `outputs/reports/`. Output paths can be
overridden with `--output` (without the extension), for example:

```bash
python scripts/evaluate_hybrid.py outputs/runs/hybrid_<timestamp>.json data/eval/ground_truth.csv --output outputs/reports/hybrid_eval
```

To compare the two report CSV files:

```bash
python scripts/compare_results.py outputs/reports/naive_eval.csv outputs/reports/hybrid_eval.csv
```

The comparison is also saved to `outputs/reports/comparison.csv` by default.

## Testing

```bash
pytest -q
```

The test suite covers configuration loading, chunking, BM25 retrieval, hybrid
retrieval, empty-corpus behavior and RAGAS dataset normalization.
